1. Vision General

Quoth es un sistema de auto-aprendizaje autonomo para Claude Code que captura trayectorias de trabajo, las procesa en patrones reutilizables, y los inyecta en sesiones futuras para mejorar la calidad de las respuestas del agente.

Principio fundamental: Cada sesion de Claude Code genera conocimiento implicito. Quoth lo hace explicito, lo evalua, y lo reutiliza automaticamente.

Componentes principales

MCP Server22 herramientas via JSON-RPC 2.0 sobre stdioquoth-plugin/mcp/
DaemonProcesa trayectorias en background (JUDGE → DISTILL → CONSOLIDATE)quoth-plugin/daemon/

Resolucion de paths (portabilidad)

Los hooks usan fs.realpathSync(__dirname) para resolver symlinks. Cuando se invoca ~/.quoth/hooks/hook-dispatch.js (symlink), Node.js resuelve __dirname al directorio real del source tree, permitiendo que path.join(__dirname, '..', 'mcp', 'handlers') encuentre los modulos correctamente.

Variables de entorno opcionales para override: QUOTH_HOME, QUOTH_PLUGIN_DIR, QUOTH_DB_MODULE

4. Motor de Inteligencia

El motor de inteligencia combina PageRank con similitud de trigramas para ranquear y recuperar conocimiento relevante. Portado de intelligence.cjs (ruflo) a modulos puros de Quoth.

Componentes

graph.js — Algoritmos

FuncionDescripcion
tokenize(text)Normaliza texto a tokens lowercase
trigrams(tokens)Genera set de trigramas de tokens consecutivos
jaccardSimilarity(a, b)Similitud Jaccard entre dos sets de trigramas (0-1)
computePageRank(nodes, edges, opts)PageRank iterativo con damping=0.85, 20 iteraciones
buildEdges(entries, threshold)Construye aristas temporales + de similitud (Jaccard > threshold)

Ciclo de vida del grafo

  1. initGraph(db) — Lee MEMORY.md files + patrones de la DB, construye nodos, calcula aristas (Jaccard > 0.15), ejecuta PageRank
  2. getContext(prompt, topK) — Genera trigramas del prompt, calcula Jaccard contra todos los nodos, retorna top-K con scores
  3. consolidateGraph(db) — Procesa pending edits, refresca desde patterns DB, aplica decay a entradas no accedidas, rebuild completo
  4. applyFeedback(success) — Ajusta confianza de los ultimos nodos matched (+0.03 exito / -0.03 fallo)

5. Daemon de Procesamiento

El daemon corre en background y procesa trayectorias capturadas usando subagentes de Claude (Haiku) para extraer patrones reutilizables.

Pipeline de procesamiento

1. JUDGE → 2. DISTILL → 3. CONSOLIDATE

FaseModeloInputOutput
JUDGEHaikuTrayectoria raw (tool calls + results)Veredicto: es patron reutilizable? (si/no + razon)
DISTILLHaikuTrayectorias aprobadasPatron destilado: nombre, accion, tags, confianza inicial
CONSOLIDATELocalPatrones destilados + existentesMerge con DB: dedup, update confianza, prune baja confianza

Configuracion del daemon

ParametroValorDescripcion
Auto-startVia hook session-startSe inicia automaticamente al abrir sesion
PID file~/.quoth/daemon.pidTracking de proceso
Log file~/.quoth/daemon.logLog de actividad
Debug modeQUOTH_DEBUG=trueVerbose logging

Scoring Bayesiano

La confianza de patrones usa distribucion Beta(alpha, beta) en lugar de incrementos simples:

  • Exito: alpha += 1 (incrementa media)
  • Fallo: beta += 1 (decrementa media)
  • Confianza = alpha / (alpha + beta) — converge con mas evidencia
  • Delta por feedback: +/-0.03 por evento

Decision Attribution

El sistema trackea que patron causo cada decision exitosa o fallida, permitiendo refinar la confianza de patrones especificos basado en outcomes reales.

Source Tagging

Cada patron tiene un tag de origen:

TagOrigen
distilledExtraido automaticamente de trayectorias via daemon
exolar-seededImportado de clusters de fallos de Exolar
healer-learnedAprendido de correcciones de errores
attributedRefinado via decision attribution
skill-derivedExtraido de tests exitosos como skills

Promocion nocturna

Patrones con confianza > 0.8 y > 10 usos se auto-promueven a Quoth Cloud (quoth.triqual.dev) a las 3am. Re-promocion solo cuando la confianza mejora > 0.1 desde el ultimo upload. Requiere QUOTH_API_KEY.

9. Sistema de Patrones

Ciclo de vida de un patron

  1. Captura: trajectory-capture.js graba tool calls en .jsonl
  2. Evaluacion: Daemon JUDGE evalua si la trayectoria es patron reutilizable
  3. Destilacion: Daemon DISTILL extrae nombre, accion, tags
  4. Almacenamiento: Se inserta en memory.db con confianza Beta(1,1) = 0.50
  5. Uso: inject-patterns.js lo inyecta en sesiones futuras si es top-8
  6. Feedback: Exito/fallo ajusta confianza via quoth_log_outcome
  7. Promocion: Si confianza > 0.8 y > 10 usos, se promueve a Quoth Cloud

Inyeccion token-optimizada

La inyeccion de patrones al inicio de sesion usa un formato comprimido para minimizar uso de contexto:

[Quoth] 8 patterns loaded
HIGH: pattern-auth(0.9), error-handling(0.8)
MED: api-design(0.6), test-setup(0.5)
Details:
- pattern-auth: Use JWT with refresh tokens, validate at middleware level...
- error-handling: Wrap external calls in try/catch, log context...
- api-design: REST endpoints follow /api/v1/{resource} convention...
Budget de tokens: Maximo 800 caracteres (~200 tokens). Patrones agrupados por tier (HIGH/MED). Solo los top 3 incluyen texto de accion completo. Reduccion: ~800 tokens (verbose) → ~200 tokens (comprimido). Reduccion del 75%.

12. Instalacion y Setup

Instalacion automatica

git clone <quoth-repo>
cd quoth-plugin
bash scripts/setup.sh

Que hace setup.sh

  1. Crea estructura ~/.quoth/ (hooks/, intelligence/, trajectories/)
  2. Symlink de 4 hook files desde source tree a ~/.quoth/hooks/
  3. Inyecta hook declarations en ~/.claude/settings.json (merge, no overwrite)
  4. Agrega permiso Bash(node .quoth/*)
  5. Muestra instrucciones para iniciar daemon
Idempotente: El script detecta si ya esta instalado y no duplica configuracion. Seguro re-ejecutar.

Verificacion

# Verificar hooks
node ~/.quoth/hooks/hook-dispatch.js stats

# Verificar MCP server (22 tools)
echo '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' | \
  node quoth-plugin/mcp/quoth-learning-server.js

# Iniciar daemon
node quoth-plugin/daemon/daemon.js &
